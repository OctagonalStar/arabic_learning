# 人工回归冒烟测试清单

## 用途

本清单用于每次 Phase 完成后、提交合并或发布前，由人工逐项执行的回归冒烟测试。项目现有少量自动化测试（`test/` 下的应用冒烟与纯逻辑单元测试），但覆盖面有限，无法替代真实设备上的端到端验证，因此本清单仍是主要的回归手段。

每次执行请覆盖全部平台回归点，重点平台为 Android、Windows、Web。失败项请记录到文末的失败记录表，不要只勾选不记录。

## 执行前提

- 已执行 `flutter pub get` 且无错误。
- 已通过 `flutter run -d <device>` 正常启动应用，`<device>` 可为目标平台设备或模拟器。
- 已准备测试素材：本地 JSON 词库文件、本地 JSONL 词库文件、可用的 WebDAV 账号、可用的 AI API 配置（阅读题生成用）。
- Web 端请使用最新构建版，注意其功能与 bug 可能多于桌面/移动端。

## 1. 启动流程

- [ ] 全新安装后首次启动显示条款页，输入用户名并点击同意后可进入主页（预期：术语内容来自 `assets/help/TermsOfUse.md`，同意后写入签署状态）。
- [ ] 条款页不输入用户名或直接点击同意时给出提示，无法进入主界面（预期：SnackBar 提示需阅读并同意条款）。
- [ ] 条款号更新后再次启动，条款页显示更新提示并要求重新确认授权（预期：提示上一版本条款有更新，同意后更新签署条款号）。
- [ ] 版本更新后启动弹出更新日志弹窗，内容与 `CHANGELOG.md` 一致且 Markdown 渲染正常（预期：`updateLogRequire` 为真时才弹出）。
- [ ] 后续正常启动直接进入主页，不再弹出条款页与更新日志（预期：已签署且版本未变）。
- [ ] 冷启动时加载页正常过渡到主页（预期：`Global.init()` 完成前显示过渡页，无白屏、无长时间卡死）。

## 回归重点

以下位置最容易回归，每次必须优先执行并重点观察：

- 存储备份键：`usedKeys` 决定哪些顶层键会进入 WebDAV 备份与本地导出。新增任何顶层存储键后，若未同步加入 `usedKeys`，该键会在备份与导出中被静默丢弃。恢复数据后必须确认调用 `Global.conveySetting()` 重建 `Config`，否则界面会继续使用恢复前的旧内存配置。
- Web 构建：Web 端使用 idb_shim IndexedDB（回退 shared_preferences），并依赖 `lib/package_replacement/` 下的 `fake_*.dart` 垫片。`sherpa_onnx` 等原生库必须保持在条件导入之后，`AppData.basePath` 在 Web 上不可读取。任何新增原生依赖都需补垫片或运行时 `kIsWeb` 守卫，否则 Web 构建会失败或运行时报错。
- 横屏溢出：主页四个 Tab、设置页、词汇总览、学习与测试页面在平板横屏或桌面小窗口下最易出现 overflow。桌面端 `window_manager` 可自由缩放，务必拖拽到极端尺寸验证。
- 深色对比度：强制深色与跟随系统切换后，检查文字、图标、卡片、选项在 11 种主题色下的对比度与可读性，尤其注意彩蛋主题色的深色表现。
